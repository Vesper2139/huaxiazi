# 中文润色盲评数据来源调查（2026-10-02）

## 结论

截至 2026-10-02，本轮检索到的公开中文改写数据可为评测维度设计、开发集压力样例或特定安全切片提供参考；没有发现一个同时满足本项目通用润色与提示词优化任务、至少 500 条冻结盲测、来源权利可追溯、数据未公开泄漏且具备本项目所需双人标注与裁定证据的数据集。公开仓库中的 license 标签不等同于对其每条上游内容、个人信息、衍生输出和本项目再分发方式的独立法律审查。

因此不导入任何公开数据到 `blind-eval.jsonl`，也不改变冻结集。后续来源核验只将一个候选 eval 文件临时下载到被忽略的 `out/external-source-audit/` 目录用于哈希、字段和隐私启发式检查；未将样本或答案纳入仓库评测资产。可公开访问的基准默认只能作为开发诊断或补充切片候选。阶段 0 的冻结集应由项目自有且可审计的任务，或用户主动脱敏并明确授权的样本构成；由独立评审者双评并对分歧裁定，访问权限与样本映射单独管理。

## 对评测协议的研究启示

- [Persona-Augmented Benchmarking（EMNLP 2025）](https://aclanthology.org/2025.emnlp-main.1155/)报告：语义内容不变时，输入风格和提示格式的变化也会改变模型评估结果。对本项目的决策是：在冻结集覆盖不同表达风格与任务措辞；按语义族整体划分，不能把同一任务的改写版本拆到开发/冻结两侧。
- [HoWToBench（ACL 2026）](https://aclanthology.org/2026.acl-long.317/)将写作质量拆分为多层子特征，并讨论传统重叠指标和常见 LLM-as-a-judge 的脆弱性。该工作是开放式写作而非润色基准；可借鉴“先分别评事实、任务完成、语气和可用性，再按预先定义规则汇总”的方法，不能直接移植其 0.93 相关系数或评分器作为本项目质量证明。
- RewritingBench 数据卡报告基于参考文本的传统指标与人工判断相关性弱，并报告 pairwise evaluator 与人评相关；因其论文身份尚未独立验证，本轮仅把它作为待核验线索。无论如何，本项目既有协议以匿名人工双评、分歧裁定和成对比较为主，不使用 BLEU/ROUGE 或单一 LLM judge 代替人评事实保真与安全判定。

## 下一步数据建设顺序

1. 先确定样本来源台账与授权/许可审查负责人；外部公开数据先作为独立候选清单，不与私有冻结集混合。
2. 通过项目自有书写场景和明确同意的脱敏用户样本，建立至少 500 条全新样本；记录 task、语义族、场景、风险级别、主导输入表达风格、授权引用、脱敏方式和来源哈希。两个任务（润色、提示词优化）均需覆盖，格式、澄清、事实约束、高风险等维度可交叉分层。输入风格覆盖用于诊断外部有效性，不按风格配额伪造真实用户分布。
3. 样本先完成去重、PII/密钥扫描和来源审查；两名评审独立标注并分别保存完整标签，第三人只裁定分歧；最终金标必须与一致评审或裁定结果一致。评审 ID 与样本身份分开封存。
4. 按语义族切分开发集/冻结集，保存不可变快照和 SHA-256；只有冻结后才采集同条件候选输出。公开基准仅在明确标记的开发/校准报告中单独呈现。
5. 统计覆盖与标注一致性后再过阶段 0 门槛；未满足授权、双评、隔离或真实云/本地基线条件前，不改生成提示、路由、个性化或权重来宣称质量提升。

### A0.1 决策

本轮没有找到可直接准入的单一公开集合。推荐两条并行但相互隔离的数据轨道：

1. **正式通用冻结集：** 仍由项目自有创作、或用户主动脱敏且明确授权的数据组成，覆盖 polish 与 prompt_optimize；至少 500 条、逐样本来源/用途核验、语义族去重和 split 隔离、两名独立评审及分歧裁定。公开基准的答案不得用于该集。
2. **公开开发诊断切片：** 仅在有明确来源权利、隐私审查和版本哈希后，分别登记 WritingBench 风格/格式要求、RewritingBench 改写和 ToxiRewriteCN 安全任务；每份单独报告公开污染与适用边界，不拼入私有冻结集、不用于训练，除非数据负责人另行审查并批准。

当前无法满足 A0.1 的关键信息仍是：数据来源/权利负责人、≥500 条项目自有或授权的通用样本、独立双评与裁定人员、受控原始证据托管。公开资料可以帮助形成开发候选，不能替代这些实际责任与证据。因此不触发下载、导入、解盲或云端调用，阶段 0 仍未通过，阶段 1 生成行为继续冻结。
