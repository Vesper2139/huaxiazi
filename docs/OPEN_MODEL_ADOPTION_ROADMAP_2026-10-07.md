# 话匣子成熟开源模型直接采用路线（无需自行训练）

更新时间：2026-10-07

## 目标

直接采用已经完成预训练/指令微调的成熟开源模型权重，验证后通过话匣子现有的模型下载与受管 llama.cpp 路径提供本地服务。**本路线不训练基础模型、不做 LoRA/SFT，也不要求用户安装训练框架。**云端 API、用户偏好上下文和本地模型继续并行可选。

## 当前判断

- 应用已有云端 Provider 与受管 GGUF/llama.cpp 本地推理路径；本地运行时和模型作为单独下载内容。
- 项目已有受管 GGUF/llama.cpp 推理、签名模型目录、下载校验和 Qwen3 模型候选；本地模型运行链已有 CPU/Vulkan 烟测证据，WPF 首次使用和干净 Windows 验收仍待完成。
- 当前目录已列出 Qwen3 1.7B、Qwen3-4B、Qwen3-4B-Instruct-2507、Qwen3-8B 等已训练权重候选。下一步是确认准确模型版本、模板、许可证、下载源和当前运行时兼容性，再进行任务质量对照。
- `training/runs/` 是历史提示/输出协议诊断记录，包含实验用 Ollama 结果；它们不是产品依赖，也不是训练交付物。后续只归档，不以训练为目标。
- `polish-agent-v2` 的重复和 split 泄漏问题会影响质量对照的结论强度，但不妨碍先验证模型下载、加载、生成和用户选择流程；禁止用该合成集宣称模型质量已提升。

## 技术选择

- **权重选择：** 只考虑成熟的 Instruct/Chat 权重，不选需要自行进行指令微调的 Base 权重。当前可从项目已配置的 Qwen3 家族候选开始，优先核对 `Qwen3-4B-Instruct-2507` 和已有 4B 标准档；较新的 Qwen3.5-4B 可作为兼容性候选，不能仅因版本更新就直接替换。
- **推理格式与运行时：** 使用项目现有 GGUF 与受管 llama.cpp，不增加 Ollama、Python、CUDA 训练环境作为产品依赖。必须对锁定 runtime、模型模板、结构化输出与 thinking 控制做真机验证。
- **模型来源：** 固定发布版本/commit、量化方式、文件 SHA-256、来源仓库、许可证、上下文限制和运行时兼容范围。社区量化文件需记录其与上游权重的关系，并审核再分发条款。
- **个性化：** 先使用现有 system/context/Skill/结构化偏好和质量门禁定制模型行为；若一个预训练好的领域/风格微调模型更贴合，再作为独立候选评估，不自行训练。
- **官方资料：** [Qwen3 模型类型说明](https://github.com/QwenLM/Qwen3/blob/main/docs/source/getting_started/concepts.md) 区分 Base 与可直接对话的 Instruct；[Qwen3.5-4B 模型卡](https://huggingface.co/Qwen/Qwen3.5-4B)列出 Apache-2.0 和默认 thinking 行为；[llama.cpp 模型文档](https://github.com/ggml-org/llama.cpp/blob/master/docs/models.md)要求 GGUF 并提供兼容模型加载方式。模型卡/上游支持说明不能替代项目锁定版本的兼容实测。

## 工作包与验收

### M0：核对现有产品链和候选模型

- 以 `Services/LocalModelCatalogService.cs` 为入口核对已登记的权重、来源、哈希、许可和硬件档位；对照 `docs/local-model-research-2026-09-27.md` 与当前受管 runtime 锁定版。
- 现有模型记录和实验目录只读保留；不下载或运行实验 Ollama。
- 从已有 4B Instruct 选择一个最小候选集；仅当当前 runtime 实测兼容时纳入新一代模型。

**完成条件：** 每个候选都有准确模型卡、来源 revision、许可、GGUF SHA-256/大小、chat template 和硬件要求；候选数量收敛至可比较的少数。

### M1：下载、校验和本地加载验证

- 复用现有模型目录和 `LocalModelDownloadService` 的下载、磁盘空间、取消、续传及 SHA 校验链路；缺失文件/哈希不符必须拒绝安装。
- 通过应用首次使用流程加载一个已登记 Instruct GGUF；CPU 与已支持硬件后端均做生成、停止、健康检查与恢复验证。
- 检查 system prompt、chat template、thinking 开关、上下文上限和输出协议是否匹配，避免把 Base/Thinking 模型当普通 Instruct 模型静默使用。

**完成条件：** 下载 SHA 通过；LocalOnly 下无外部 API；能完整润色；停止、重启、取消和失败错误可解释；不自动切换到云端。

### M2：同条件任务质量比较

- 将已训练的开源候选与现有本地基线、配置的云端模型作配对比较，保持相同任务输入、产品上下文、采样参数、解析器和质量规则。
- 当前合成/内部数据只用于格式、事实锚点、澄清和协议的冒烟回归，不声称真实用户收益；正式质量结论仍需授权并隔离的评测数据。
- 记录结果模型标识、延迟、用量（云端）、tokens/s/内存峰值（本地）和匿名质量标注，不记录请求正文到遥测。

**完成条件：** 候选本地模型满足结构/事实/安全门禁；配对人工偏好支持有意义的提升；硬件档位、延迟与质量取舍明确。

### M3：整理模型目录并交付

- 将通过的候选准确登记到签名目录；保留手动选择和“仅本地”策略，默认模型变更需有比较证据。
- 用户可看到正在使用的模型名称、版本、量化、占用空间和性能档位；下载与卸载行为由用户控制。
- 独立交付模型和 runtime，不增加主安装包体积；保持实验 Ollama 与产品链路完全分开。

**完成条件：** 签名清单、许可和 SHA 通过；安装/更新/卸载可用；手动模型选择生效；主包保持轻量。

## 立即执行顺序

1. 核实当前产品内 Qwen3-4B Instruct 2507/官方 GGUF 两个 4B 候选及其目录信息。
2. 以现有受管 llama.cpp b11424 跑模型加载、chat template、输出协议和 CPU/Vulkan 冒烟；兼容失败的新模型暂不放入默认目录。
3. 使用质量有效的当前盲评数据；在未就绪时只报告链路冒烟，不生成“模型更优”结论。
4. 通过对照后更新签名模型目录和用户说明，维持可选择、可卸载与仅本地保证。

## 明确不做

- 不训练基础模型、不运行 LoRA/SFT，不维护 LLaMA-Factory、Unsloth、TRL 等训练工具链。
- 不在 WPF 主程序嵌入 Python、CUDA 或训练环境。
- 不把实验 Ollama 当作产品本地模型或发布验收依赖。
- 不把未经验证的社区模型权重直接设为默认；不以模型规模、发布日期或模型方 benchmark 代替本项目任务评测。
