# 智能编排与质量保障

## 目标与边界

智能编排以“更少操作获得可直接使用、忠于原意的成稿”为目标。分类结果属于内部路由信息，默认不增加用户标签、表单或模型参数设置。用户明确要求始终高于来源应用、历史偏好和本地推断。

系统不训练模型，也不针对 Temperature、Top P 做大规模组合调参。优先使用确定性规则、结构化提示、按风险校验和真实编辑反馈。

## 请求链路

1. `InputContextParser` 解析用户主动写出的上下文。
2. `ForegroundApplicationContextService` 只把前台进程归约为“邮件客户端、企业通讯、代码编辑器”等粗粒度信息，不读取或上传窗口标题。
3. `SmartContextAnalyzer` 在本地推断场景、渠道、目的、正式度、风险等级，并提取日期、金额、数量等保真锚点。
4. 显式上下文覆盖本地推断；来源应用仅在文字没有更强证据时生效。
5. `PolishPromptBuilderService` 把策略和元数据放入 system message，原文只放入 user message。
6. `PolishFidelityValidator` 检查事实锚点和不确定表述。首次失败时只自动修复一次；再次失败则阻止展示和归档。
7. 用户主动编辑并保存时，归档记录本次“模型稿 → 用户稿”的显式证据。`AdaptivePreferenceService` 只在同一表达被至少两次删除后形成禁用词偏好；改写强度则要求至少三次、且大多数编辑都显著缩短成稿后，才形成“优先简洁、减少铺垫”的结构化偏好，避免一次编辑造成过拟合。

## 隐私规则

- 无痕模式不读取历史偏好。
- 关闭历史后不使用历史偏好。
- 关闭优化稿保存后，不在归档上下文中保留用于学习的模型稿。
- 来源应用只保留粗粒度类型，不保存进程名、窗口标题或文档标题。
- 来源应用按邮件、企业通讯、即时通讯、代码编辑器和文档编辑器等家族归约；浏览器或未知应用不擅自推断沟通场景。
- 用户原文不进入 system message，避免角色边界混乱和重复 Token。

## 质量回归指标

当前自动测试覆盖：

- 私人、职场、公开发布与来源应用的保守路由；
- 显式上下文覆盖推断；
- 日期、数量等事实锚点保留；
- 不确定表述不得强化为确定承诺；
- 首次失败自动修复、二次失败阻止归档；
- 原文 System/User 消息隔离；
- 用户重复删改偏好和隐私保留开关。

后续扩充真实脱敏语料时，应重点跟踪：直接采用率、编辑距离、重新生成率、事实遗漏率、承诺强化率、P50/P95 延迟和单次平均调用数。不要只使用主观“文案更好看”作为验收标准。
