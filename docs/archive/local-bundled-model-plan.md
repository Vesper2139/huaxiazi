# 轻量化本地模型随包方案：历史提案

> **本提案已被当前交付策略替代。** 现行方案保持主安装包轻量，GGUF 模型与 llama.cpp runtime 由用户按需独立下载；请以 [STATUS.md](../STATUS.md)、[ROADMAP.md](../ROADMAP.md) 和 [成熟开源模型直接采用路线](../OPEN_MODEL_ADOPTION_ROADMAP_2026-10-07.md) 为准。本文保留早期“模型随包”方案的背景，不构成当前发布要求。

## 1. 目标与结论

目标是让用户安装“话匣子”后，无需 API Key、无需登录、无需额外安装 Ollama，即可完成中文润色、语法纠错、语气改写和基础提示词整理。

推荐采用“两层能力 + 一个内置模型”的结构：

1. **规则层**：处理标点、空格、数字、日期、专名保护、敏感片段保护和输出格式校验。
2. **内置本地模型层**：随应用安装的量化模型负责语义级润色和风格改写。
3. **可选升级层**：用户有更高质量要求时，再下载 8B 或更大模型；不影响首装即可用。

默认推荐：

| 安装档位 | 默认模型 | 预计模型文件 | 建议设备 | 适用范围 |
|---|---|---:|---|---|
| 极轻版 | Qwen3-1.7B-Instruct，Q4 量化 | 约 1.2～1.8 GB | 8 GB 内存、普通 CPU | 短句改写、错别字、基础语气调整 |
| 标准版（推荐） | Qwen3-4B-Instruct，Q4 量化 | 约 2.5～3.5 GB | 8～16 GB 内存 | 中文润色、职场表达、公文和提示词改写 |
| 高质量升级版 | Qwen3-8B-Instruct，Q4 量化 | 约 5～6 GB | 16 GB 以上内存 | 长文本、复杂语义、风格约束、多轮改写 |

如果产品必须做到“小安装包”，默认内置 1.7B；如果产品更重视首装后的可用质量，默认内置 4B。对于本项目的润色定位，**标准版 Qwen3-4B Q4 是综合推荐**。

体积是工程估算，实际取决于 GGUF 量化格式、词表、运行时和打包方式，应以最终构建产物为准。

## 2. 为什么不把大模型作为默认内置模型

GLM-4.7-Flash、gpt-oss-20b、DeepSeek V4 Flash 等模型更适合复杂 Agent、工具调用或高质量长上下文任务，但其权重、内存和启动成本不适合每个用户的默认安装包。它们应作为独立的“高质量模型包”或企业版资源，不应阻塞普通用户首次启动。

默认模型应优先满足：

- 能在 CPU 上运行，低端设备不会完全不可用；
- 首次启动无需联网、无需服务端账号；
- 支持中文和中英混合输入；
- 量化后体积可接受；
- 可以通过统一接口替换为更大模型；
- 许可证和再分发边界清楚。

Qwen3 系列目前最适合作为本项目的默认候选；模型选型和许可证仍应在正式发布前按具体版本重新核验。

## 3. 推荐运行架构

```text
WPF 界面
  ↓
LocalModelProvider（统一模型提供者接口）
  ↓
PromptPipeline
  ├─ 输入清洗与片段保护
  ├─ 任务分类：纠错 / 润色 / 改写 / 提示词整理
  ├─ 本地模型推理
  ├─ 输出解析与格式校验
  └─ 失败重试或规则降级
  ↓
本地结果
```

当前项目已有外部 Provider 抽象，因此新增本地能力时不应把推理逻辑写进界面层。建议新增：

```text
PromptFloat/Services/LocalModel/
  ILocalModelProvider.cs
  LocalModelProvider.cs
  LocalModelManifest.cs
  LocalModelHealthCheck.cs
  LocalModelPromptBuilder.cs
```

运行时首选 `llama.cpp + GGUF`，原因是部署简单、CPU 兼容性好、模型文件易于独立管理。可以通过原生库或受控子进程调用，但上层必须保持 Provider 接口不变，未来才能切换 ONNX Runtime、DirectML、CUDA 或其他后端。

不建议把 Ollama 作为用户前置依赖：它会引入额外安装、后台服务、版本耦合和用户理解成本。开发者可以用 Ollama 做实验，正式发行版应尽量自带运行时。

## 4. 安装包组织

模型不建议作为 WPF 资源嵌入程序集，而应作为受校验的外部只读文件随安装包发布：

```text
话匣子/
  PromptFloat.exe
  runtimes/
    win-x64/
      llama.dll
  models/
    manifest.json
    qwen3-4b-instruct-q4.gguf
  prompts/
  skills/
  Config/
```

建议的模型清单：

```json
{
  "schema_version": 1,
  "model_id": "qwen3-4b-instruct-q4",
  "display_name": "话匣子内置中文润色模型",
  "format": "gguf",
  "quantization": "Q4_K_M",
  "context_tokens": 8192,
  "default_max_output_tokens": 1024,
  "sha256": "发布时填写实际哈希",
  "license_notice": "随发布包附带完整许可证和模型说明"
}
```

安装策略分为两种：

- **完整离线安装包**：模型和运行时全部随包，适合用户明确要求“下载即用”。
- **小引导安装包**：只包含程序，首次启动下载同一模型包，适合官网或应用商店的首包限制。

即使提供小引导安装包，也应保证“模型包版本固定、可校验、可断点续传、下载失败后可重新安装”，不能让用户进入无模型的死路。

## 5. 推理参数与任务路由

标准润色默认建议：

```text
temperature: 0.2～0.45
top_p: 0.8～0.95
max_output_tokens: 512～1024
context: 4096～8192
thinking: 关闭或使用非思考模式
```

推荐按任务路由：

| 任务 | 处理方式 | 默认模型 |
|---|---|---|
| 标点、空格、数字、格式 | 规则层优先 | 不调用模型或调用 1.7B |
| 一句话润色 | 1.7B/4B | 4B |
| 职场和公文表达 | 4B | 4B |
| 多版本语气改写 | 4B | 4B |
| 长文重写、结构优化 | 可选升级模型 | 8B |
| 复杂提示词设计、工具调用 | 高质量升级模型 | 8B 以上 |

这能让小模型承担高频、短文本任务，把速度和内存压力控制在可接受范围内。

## 6. 质量与安全控制

本地模型不能直接把输出交给用户，必须经过后处理：

1. 保护 URL、数字、日期、金额、专有名词、代码、变量名和用户指定不可修改片段。
2. 检查输出是否为空、是否无故增加事实、是否改变数字和否定关系。
3. 对“仅纠错”任务禁止大幅改写；对“风格改写”任务允许句式变化但保留事实。
4. 输出无法解析时，返回原文并提示用户重试，而不是展示半截内容。
5. 长文本按段落切分，避免一次推理撑满上下文。
6. 模型文件只读、启动时校验 SHA-256，模型目录与用户数据目录分离。
7. 默认不上传文本；界面明确标注“本地处理”或“外部模型处理”。

本地模型的最低验收集应覆盖：

- 错别字和标点纠错；
- 口语转正式表达；
- 职场消息礼貌化；
- 公文句式压缩；
- 申论段落润色；
- 保留数字、时间、专名和否定词；
- 不编造政策、数据和事实；
- 空输入、超长输入和混合中英文输入。

## 7. 与现有训练数据库的衔接

当前 `PromptFloat/datasets/polish-agent-v2` 可作为监督学习的第一版数据准备层，但它不是模型本身。推荐增加以下字段或派生视图：

```text
task_type
input_text
constraints
reference_output
quality_flags
source_id
split
model_target
```

训练和部署的关系：

```text
现有 SFT 数据
  → 数据清洗与人工抽检
  → 4B 基座模型 LoRA/QLoRA（后续阶段）
  → 适配器或合并权重
  → GGUF 量化
  → 本地模型验收
  → 随包发布
```

当前阶段不进行实际训练，只需保证数据格式能同时支持：

- 基座模型直接推理；
- 后续 SFT/LoRA；
- 规则层回归测试；
- 不同模型横向对比。

后续如果训练出 LoRA 适配器，优先把适配器作为独立升级包发布，而不是立即替换所有用户的基座模型。这样可以控制升级风险和下载体积。

## 8. 发布路线

### 阶段 A：能力骨架（当前实现）

- 已接入 `LocalModelProvider` 与 GGUF 下载/导入、哈希校验；
- 当前仓库不包含 Qwen3-4B GGUF 或 `llama-server.exe`，因此本阶段不宣称“安装即用”；
- 无 `runtimes/local` 时，设置页隐藏受管本地模型入口，避免用户下载模型后才发现无法推理；
- 只有随包运行时和真实 GGUF 端到端验收均通过后，才能升级为“阶段 A：随包可用”。

### 阶段 B：低配兼容

- 增加 1.7B Q4 资源；
- 首次启动根据内存和 CPU 选择模型；
- 低配设备使用规则层 + 1.7B；
- 支持用户手动切换模型。

### 阶段 C：高质量升级

- 提供 8B Q4 下载包；
- 增加长文本和复杂改写评测；
- 支持 LoRA 适配器；
- 对模型、运行时和训练数据分别版本化。

## 9. 最终建议

如果产品定位是“每个用户安装后立刻能用”，采用下面的默认配置：

```text
默认随包：Qwen3-4B-Instruct Q4_K_M
运行时：llama.cpp / GGUF
默认上下文：8192 tokens
默认输出：1024 tokens
本地服务：应用内 LocalModelProvider
规则层：标点、数字、专名、格式和事实保护
升级包：Qwen3-8B Q4
复杂 Agent：不放入默认包，另行提供高质量模型包
```

若必须将完整安装包控制在约 2 GB 以内，则退回 Qwen3-1.7B Q4，并通过规则层和任务路由补足能力；这会牺牲复杂润色质量，但仍能覆盖基础纠错和短句改写。
