# 话匣子 AI 评测集去重与冻结规则

版本：1.0

适用协议：`huaxiazi-blind-evaluation-admission` v3.0

状态：操作规程草案；尚未冻结真实外部评测集。

## 1. 去重目标和边界

去重是为了避免相同或近似任务同时出现在开发集与冻结测试集，导致测试结果被记忆、模板复用或同源变体虚高。它不意味着自动删除所有表达相似的合法样本，也不能由文本相似度工具独立决定授权、任务等价或风险级别。

至少执行两层检查：

1. **精确输入重复**：保留原始文本不变，另计算用于核对的规范化键。当前 `blind-validate` 对输入执行 `Trim()` 后检查完全相同字符串及跨 split 重复；它不会替代语义近重复审查，也不会自动做大小写、标点、繁简或数字归一化。
2. **语义族归并**：由两名数据整理者独立判断样本是否来自同一底层任务/情境，或是否只是替换专名、数字、语气词、格式后仍共享同一事实结构、约束和预期决策。确定相关时使用同一不透明 `semantic_family_id`，整个 family 只能进入一个 split。分歧交第三人裁定并留受控记录。

仅共享常见表达、主题词或任务类型不自动归为同一 family。若成员共享会导致参考答案或关键约束可互相推断，则应归同一 family；无法确定时按更严格边界合并并记录依据。相同来源可含多个无关 family；同一 family 也不得因来源记录不同而拆分到不同 split。

## 2. 整理顺序与职责

1. 来源负责人先核对来源登记、用途范围、脱敏状态和撤回条件。未核验来源不进入候选冻结池。
2. 数据整理者为样本分配随机 `id`，保留受控来源映射；对原始输入做精确重复检查，并独立标注语义族关系。不得用模型生成或改写冻结测试输入来“增加数量”。
3. 两名金标评审独立完成 v3 全字段标签；分歧由第三人裁定。任何用于改写/补充输入的人员不得查看候选模型输出。
4. 由不参与模型候选运行的评测保管人按 family 分组后分配 `development` / `frozen_test`。分配方法、随机种子或抽签记录、分层规则及例外理由存于受控审计记录。随后检查协议配额、split 内覆盖及与 canonical train/dev 的交叉泄漏。
5. `DatasetBuilder blind-validate` 通过只说明当前程序检查项通过。整理者还要人工复核 family 表、授权覆盖、盲评记录和冻结测试访问日志。

不得为了满足配额而拆分语义族，或在看到候选测试结果后移动样本、调比例、改金标。若配额不足，应继续取得合格新来源或样本并重新分配整个候选池，然后重新冻结。

## 3. 冻结包及保管

每个冻结版本至少绑定以下内容的 SHA-256 和版本标识：

- `blind-eval.jsonl` 原始字节及 `blind-eval.schema.json`；
- 本目录的标注手册、准入协议版本/规则 hash、去重与冻结规则；
- 来源登记快照及授权证据的受控 vault 引用；
- 独立评审盲包、两份原始标签、争议裁定、分配/身份隔离审计证据；
- admission 报告、工具版本/源码提交、运行基线配置和每个候选的实际提示/参数/模型身份封存材料。

冻结数据和身份映射、来源原件、盲包分发材料必须分开授权访问。候选模型运行人只接收必要输入快照；评审者看不到 gold、模型身份或其他评审答案。冻结测试输出仅由授权评测保管人解封并汇总。

仓库中的 SHA-256、证据索引与 create-only 报告能帮助核对字节一致性；它们不等于不可变存储、数字签名、可信时间戳或访问控制。受控保管系统必须自行启用版本锁定/审计日志、最小权限和备份保留策略。除非后续工具验证了签名链，不得声称当前 manifest 有签名防篡改能力。

## 4. 变更、撤回和重冻结

每次冻结、受控核验、授权变化、标注更正、手册/协议升级、样本加入/移除、split 调整或工具版本变化均追加一条事件到受控 append-only 变更日志。事件至少包括不透明事件 ID、UTC 时间、变更类别、前后 artifact hash、理由引用、批准/执行角色引用和受控证据引用。不得把原始文本、个人信息、授权原件或身份映射复制进普通变更日志。

旧冻结包保持只读且不可覆盖。任何影响输入、gold、切分、许可、标注指南、准入规则、提示/采样或候选集合的变化，都产生新版本和新 hash；明确标注哪些旧基线不再可比。撤回/到期样本立即停止用于新运行，并按授权条款从活动数据、缓存和备份处理删除或隔离；随之产生的新冻结集必须重新执行完整准入与泄漏审计。不得通过改写旧报告掩盖撤回或更正。

## 5. 冻结检查清单

- [ ] 所有来源权利与候选推理、人工评审用途均经独立复核，授权仍有效。
- [ ] 疑似个人信息完成人工脱敏复核；自动扫描仅作筛查。
- [ ] 精确输入重复和语义族映射已人工审查，family 不跨 split 或训练/开发数据。
- [ ] 金标双评完整；分歧裁定者独立且最终 gold 与裁定一致。
- [ ] 总集及各 split 通过准入协议比例与风格覆盖门槛。
- [ ] 数据、Schema、协议、手册、来源登记和冻结策略版本/hash 已记录。
- [ ] 冻结测试访问、候选身份封存与评审盲化由独立保管人复核。
- [ ] 受控保管、审计日志、撤回和备份删除路径已确认。
- [ ] 运行配置、模型/运行时身份、提示 bundle、采样参数和实际硬件已冻结。

任何一项缺失，都只能标记为“冻结准备中”或“工具检查通过”，不能判定阶段 0 通过。
